# 阶段一 · 第 1-2 课讲义

## 1. 一张图看懂本阶段

```
┌─────────────────────────────────────────────────┐
│              你写的 Python 程序（客户端）           │
│                                                 │
│   messages = [system, user, assistant, user...] │  ← "记忆"就是这个列表
│        ▲                                   │    │
│        │ 3.回复追加进列表                    │ 1.全量历史 POST 上去
└────────┼───────────────────────────────────┼────┘
         │                                   ▼
   ┌─────┴──────────────────────────────────────┐
   │        LLM 服务端（无状态，用完即忘）          │
   │   只做一件事：根据收到的全部文本，            │
   │   预测下一个 token，直到生成完整回复          │
   └────────────────────────────────────────────┘
```

**必须刻进脑子的一句话：LLM 是无状态的函数，"记忆"是客户端维护的列表。**

## 2. messages 的三种角色

| role | 谁在说 | 用途 | 面试问法 |
|------|--------|------|----------|
| `system` | 开发者 | 设定人格、规则、输出格式约束 | "system prompt 和 user prompt 的区别？" |
| `user` | 用户 | 提问/指令 | — |
| `assistant` | 模型 | 模型历史回复 | "为什么要把 assistant 回复也放进 messages？"（答：模型需要知道自己说过什么，否则无法连贯追问） |

后续第 3 课会引入第 4 种消息 `tool`（工具结果），先埋个伏笔。

## 3. temperature 直觉

- `0`：每一步都选概率最高的 token → 输出几乎确定 → **抽取、分类、代码**用这个
- `0.7`：适当发散 → 日常对话默认值
- `1.0+`：明显随机 → 创意写作；**生产环境的 Agent 主流程不建议**，因为你需要行为可复现

## 4. 为什么要先裸 API 再学框架？

LangChain 本质上帮你做了三件事：
1. **模型抽象**：`ChatOpenAI` / `ChatZhipuAI` 统一了不同厂商的调用方式
2. **消息/提示词模板**：拼接 messages 的语法糖
3. **Agent 循环**：把"模型决定调哪个工具 → 执行 → 结果回填"这段循环代码封装好

不先写裸代码，你不知道它封装了什么；面试官问"框架挂了你怎么办"，裸 API 能力就是答案。**框架是加速器，不是遮羞布。**

# 阶段一 · 第 3 课讲义：工具调用 Agent

## 1. 一句话定义（背下来，面试用）

> **Agent = LLM + 工具 + 循环。** LLM 只负责决策（调哪个工具、传什么参数），
> 从不执行工具；执行发生在客户端代码里；结果回填消息历史，循环直到模型给出最终回答。

## 2. 时序图（对照 03_tool_call_bare.py 第 4 部分逐行读）

```
你: "晋江天气如何？"
   │ ① POST messages（含工具说明书 TOOL_SCHEMAS）
   ▼
模型 ──返回──> tool_calls=[get_weather({"city":"晋江"})]     ← 只是JSON意图，模型没执行任何东西
   │ ② 客户端执行真正的 HTTP 请求（wttr.in）
   │ ③ 追加 assistant(tool_calls) 消息 → 追加 tool 消息（tool_call_id 对账）
   │ ④ 带全量历史再请求
   ▼
模型 ──返回──> "晋江晴，25℃（来源：wttr.in）"  ← 无 tool_calls = 终态，循环结束
```

## 3. ReAct vs Function Calling（面试对比题）

| | ReAct（2022论文） | Native Function Calling（现代主流） |
|---|---|---|
| 原理 | 用提示词让模型按 `Thought/Action/Observation` 文本格式输出，客户端用**正则解析** | 模型厂商**训练时就会**输出结构化 tool_calls JSON |
| 可靠性 | 差（模型格式稍歪就解析失败） | 高（结构化，API 保证） |
| 历史地位 | 概念奠基人——"推理+行动交替"的思想沿用至今 | 现在所有主流模型/框架的默认实现 |
| 面试话术 | "ReAct 是思想，Function Calling 是现代落地；旧教程的 AgentExecutor 已被 1.x 移除" | |

## 4. 工程细节四条（面试加分项）

1. **工具参数是 JSON 字符串**不是字典——`arguments` 要手动 `json.loads`（03 有注释）
2. **循环必须有上限**（MAX_STEPS）：模型可能无限循环调工具，烧钱且卡死
3. **错误也要回喂**：工具返回 `{"error":...}` 交给模型，它可能自己重试/换参数/告知用户——这是 Agent 的自主恢复能力，直接抛异常终止是聊天机器人思维
4. **工具说明书（description）质量决定调用准确率**：模型看不见函数体，只看得见 schema

## 5. MCP 是什么（一段话，面试常问）

Model Context Protocol：2024 底 Anthropic 推的开放协议，把"工具/资源接入"标准化成
客户端-服务器架构——工具跑在独立 MCP Server 里，任何 Agent（Claude/Cursor/你的程序）
都能即插即用。定位：**USB-C 之于外设，MCP 之于 Agent 工具**。第 6 课实战用到。
