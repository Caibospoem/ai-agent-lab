# 阶段二 · 第 5 课讲义：对话记忆策略

## 1. 记忆为什么是问题（窗口约束的对话版）

回收第 2 课思考题 3 和第 4 课思考题 1 的结论：上下文窗口放不下、全量重发成本平方级、
长上下文中段信息被模型忽略（lost in the middle）。把这三条套到"多轮对话"上，
就是记忆问题：**聊得越久，要么忘得越多（截断），要么越贵（全存）。**

## 2. 三层记忆架构（产品级做法，ChatGPT/Claude 的记忆功能同构）

| 层 | 存什么 | 生命周期 | 解决什么 |
|---|---|---|---|
| 短期 | 最近 N 条原文，一字不动 | 当前会话 | 上下文连贯（代词、"刚才说的"） |
| 中期 | 滚动摘要（LLM 压缩） | 跨越截断 | 早期对话的 gist（大致讲过什么） |
| 长期 | 历史问答向量化入库 | 跨会话 | 具体事实检索（名字、数字、承诺） |

**核心洞察：记忆 = 对话历史上的 RAG。** 第 4 课的 embed + cosine + top-k
一行不用改，检索对象从"知识文档"换成"历史对话"——你已经会了。

## 3. 分工与互补（为什么缺一不可）

- 摘要保不住细节：让它压缩"我叫刘曾，阈值 0.33"，120 字限制下数字容易丢
  → 所以**具体事实的召回必须靠向量检索**，摘要只兜"大致聊过"的背景
- 向量检索会漏：问题换个说法，分数可能低于直觉预期（第 4 课 A 股实验）
  → 所以摘要+原文兜底，检索锦上添花
- 02_memory.py 里每轮打印三层的实时状态（短期几条/摘要有无/检索命中几分），
  跑一遍把每轮的 state 变化看懂，比读十遍讲义有用

## 4. 生产视角（面试考点）

- **指令式记忆**：ChatGPT 的 memory 主要不是全量入库，而是"记住：xxx"显式指令
  触发入库——噪音少、可控、用户有掌控感（作业 B 你会自己实现一遍）
- **记忆库与知识库分开**：生命周期不同（知识基本不变、记忆持续增长）、
  权限不同（记忆是用户私有、知识是全局）、语义分布不同（闲聊 vs 领域文档）
- **成本结构**：短期决定每轮基础成本，长期记忆只加 top-k 条——
  不会随历史增长线性变贵
