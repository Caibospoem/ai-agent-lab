# 阶段二 · 第 4 课讲义：RAG 从手写到标准件

> 修正版说明：此前讲义假设你"手写过合规平台的 RAG"——事实是那些代码由 AI 生成、
> 你尚不能完全讲清。没关系，这正是训练营要修的东西。本讲义改为两级对照：
> **00（手写版，真·手写）→ 01（标准件版）**，学完后你能防守自己简历里的项目。

## 1. RAG 是什么（不假设任何基础）

RAG 三步曲，全部逻辑就这么多：

```
① 入库：每条知识 → 转成向量（一串数字）→ 存起来
② 检索：问题 → 转成向量 → 和库里每条算余弦相似度 → 排序取 top-k
③ 生成：命中的知识塞进 prompt → 模型照着答，并注明引用
```

余弦相似度 = 两个向量方向有多接近（1=同向，0=无关）。手算例子见
`00_rag_from_scratch.py` 开头注释：(1,0,1) 与 (1,1,0) 的 cos = 1/(√2·√2) = 0.5。

**为什么需要 RAG**（回收第 2 课思考题 3）：上下文窗口放不下所有知识 +
按需检索省 token + 答案可溯源。一句话：**上下文窗口小，才需要 RAG。**

## 2. 阈值 0.33 到底是什么（你简历项目里那个"AI 调的数"）

检索会给每个候选片段打一个相关分（0~1）。阈值是一道闸门：

- 低于阈值的片段 = 无关噪音，塞进 prompt 只会把模型带偏 → 扔掉
- 所有片段都低于阈值 = 库里根本没有答案 → **直接拒答，连 LLM 都不调**（省钱+可控）

跑一遍 `00` 的两个实验你就看见了：库内问题 0.462 过线、库外问题最高 0.298 全灭。
阈值是 AI 帮你调的没关系——**你能解释它为什么存在、调高调低各牺牲什么，它就是你的**。

## 3. 两级代码对照（先手写后框架，和阶段一 03→04 同一教学法）

| 00 手写版（00_rag_from_scratch.py） | 01 标准件版（01_rag_langchain.py） |
|---|---|
| `embed_texts()`：手调 embeddings API | `OpenAIEmbeddings`（同一件事的接口封装） |
| `cosine()`：6 行手写数学 | `InMemoryVectorStore` 内部做的事 |
| `retrieve()`：手写排序 + `THRESHOLD` 过滤 | `as_retriever(search_kwargs={"k":3})` |
| `generate()`：手拼 prompt 调 glm | `ChatPromptTemplate` + LCEL 链 |

**标准件的价值**：接口统一 → 换向量库/嵌入模型不动业务代码。
**你的差异化**：00 里每 30 行就是某个标准件的内部——面试能往下讲三层的人极少。

## 4. 检索质量决定 RAG 上限（第 5 课钩子）

向量检索的两种死法：
1. 用词不同、语义相同（"降本" vs "节约成本"）→ embedding 能救
2. 精确匹配型（工单号、错误码、人名缩写）→ embedding 经常救不了 → 混合检索（关键词+向量），第 5 课

盯 RAG 先盯检索：两个脚本都把每次命中的分数打印出来，养成这个习惯。

## 5. 期望边界（你简历项目里的防线，现在讲清原理）

- **检索层**：全库低于阈值 → 拒答，不调 LLM（00 的实验二就是它）
- **生成层**：prompt 写死"参考知识不足就说没有，禁止编造"
- 两层都要：只有检索层 → 用户换个问法就穿透；只有 prompt 层 → 模型偶尔还是编。

## 6. 面试一句话：RAG vs 微调

> 知识更新频繁、要溯源、要控成本 → RAG；固定领域的行为风格需要内化 → 微调。
> 企业知识问答首选 RAG，两者可组合。
