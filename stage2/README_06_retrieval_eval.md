# 阶段二 · 第 6 课讲义：混合检索 + RAG 评测（收官）

## 1. 向量检索的两种死法（第 4 课埋的钩子，这课收）

| 死法 | 例子 | 解药 |
|---|---|---|
| ① 用词不同语义相同 | "连不上数据库" vs "数据库连接超时" | 语义向量 |
| ② 精确匹配型 | 错误码 E-4021、工单号、人名 | 关键词（bigram/BM25） |

第②种是向量检索的经典翻车现场：`E-4021` 和 `报错排查` 在向量空间里毫无关系，
但关键词一抓一个准。生产 RAG 标配 = **两路都跑，RRF 融合**。

## 2. RRF：为什么融合排名而不是分数

余弦 0~1，BM25 无上界——**量纲不可比，加权平均没有意义**。
RRF 只看排名：每路贡献 1/(60+rank)，两路相加。免归一化、对分数分布鲁棒，
60 这个常数不敏感（排名平滑器），面试可以直接报"Reciprocal Rank Fusion, k=60"。

## 3. 评测三件套：没有评测的调优是玄学

- **标注集**：query → 哪条知识该被召回。几十条人工标注就够起步
- **Recall@k**：该召回的进没进前 k（衡量"漏没漏"）——这是 RAG 调优的北极星指标
- **MRR**：正确答案排第几（1/名次）——衡量"用户要翻几条才看到对的"

有了指标，你作业 C 里那个 0.5 就不再是拍脑袋：**阈值、k、融合权重都可以拿
标注集扫出来**。这就是"评测驱动调优"，也是 MT30 那个 0.33 该有的来历。

## 4. 成本哲学：先便宜后贵（面试考点）

提升检索质量的路：换更大 embedding 模型（贵、要重嵌全库）→ 加 rerank（每 query
多一次模型调用）→ 混合检索（多一次关键词打分，**几乎零成本**）。
工程顺序永远从最便宜的做起，用评测集验证花出去的每一分钱买到了多少 Recall。
